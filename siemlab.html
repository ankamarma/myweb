SIEM Network Monitoring & Detection

A simple security monitoring lab using network devices, Suricata IDS, and Splunk SIEM to collect logs and detect network security activity.

1. Network Topology

The network monitoring environment uses network devices and endpoint systems to generate security telemetry. Suricata monitors network traffic and sends detected security events to Splunk. Endpoint logs are also collected by Splunk for centralized monitoring and investigation.

3. Nmap Scan Test

Nmap Network Scan

An Nmap scan was performed to generate reconnaissance traffic against the monitored network. The purpose of this test was to verify that network scanning activity could be observed by the IDS and forwarded to Splunk.

How the test is detected
  1. Nmap generates scanning traffic.
  2. Suricata observes the network traffic.
  3. Suricata checks the traffic against its rules.
  4. A matching security event is generated.
  5. The event is forwarded to Splunk.
  6. The event can be searched and investigated in Splunk.
Nmap scan test evidence

4. Brute-Force Attack Test

Hydra Brute-Force Test

Hydra was used to generate repeated authentication attempts against the test service. This validates whether repeated login activity can be detected and forwarded to the SIEM.

How the test is detected
  1. Hydra generates repeated authentication attempts.
  2. The traffic reaches the monitored network.
  3. Suricata inspects the traffic.
  4. Configured rules identify matching activity.
  5. Suricata creates a security event.
  6. The event is forwarded to Splunk for investigation.

7. Conclusion

This lab demonstrates an end-to-end security monitoring workflow. Endpoint logs are sent to Splunk, while network activity is inspected by Suricata and the resulting security events are forwarded to Splunk.

The Nmap and Hydra tests were used to validate the detection workflow and demonstrate how suspicious network activity can be identified and investigated through the SIEM.
